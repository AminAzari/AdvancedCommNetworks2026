## 1. چرا QoS؟

### مسئله: همه ترافیک‌ها برابر نیستند

کاربردهای مختلف نیازمندی‌های شبکه‌ای اساساً متفاوتی دارند:

| خدمت | تحمل تأخیر | تحمل اتلاف | پهنای باند | الگو |
|---------|----------------|----------------|-----------|---------|
| صدا (VoLTE) | بسیار کم (کمتر از 150ms) | کم (کمتر از 1%) | کم (64 kbps) | ثابت |
| تماس ویدیویی | کم (کمتر از 300ms) | کم (کمتر از 1%) | متوسط (1-5 Mbps) | متغیر |
| پخش جریانی ویدیو | متوسط (بافر کمتر از 5s) | بسیار کم | بالا (5-25 Mbps) | انفجاری |
| حسگر IoT | بالا (ثانیه‌ها) | بسیار کم | بسیار کم (kbps) | دوره‌ای |
| مرور وب | متوسط (کمتر از 1s) | هیچ (بازارسال TCP) | متغیر | انفجاری |
| ایمیل | بالا (ثانیه‌ها) | هیچ (بازارسال TCP) | کم | انفجاری |
| رانندگی خودران | فوق‌العاده کم (کمتر از 10ms) | فوق‌العاده کم | متوسط | ثابت |

### بدون QoS:
- تماس‌های صوتی در حین ازدحام بریده‌بریده می‌شوند
- ویدیو متوقف می‌شود در حالی که دانلودهای پس‌زمینه ادامه دارند
- خدمات اضطراری با شبکه‌های اجتماعی رقابت می‌کنند
- بسته‌های کنترل صنعتی توسط انتقال‌های انبوه به تأخیر می‌افتند

### هدف QoS:
**تمایز ترافیک و ارائه رفتار مناسب به هر خدمت بر اساس نیازمندی‌های آن.**

## 2. تحول QoS در نسل‌ها

```
┌─────────────────────────────────────────────────────────────────────┐
│                    QoS EVOLUTION TIMELINE                            │
├──────────┬──────────────┬───────────────────┬───────────────────────┤
│   2G     │     3G       │      LTE (4G)     │       5G NR           │
│          │              │                   │                       │
│ No QoS   │ 4 Traffic    │ Bearer-Based QoS  │ Flow-Based QoS        │
│ (all     │ Classes      │ (QCI + Bearer)    │ (5QI + QoS Flow)      │
│ circuit- │              │                   │                       │
│ switched)│ Conversational│ 9 Standard QCIs  │ 90 Standard 5QIs      │
│          │ Streaming    │ GBR/Non-GBR      │ GBR/Non-GBR/DC-GBR   │
│ Same     │ Interactive  │ Default+Dedicated │ Reflective QoS        │
│ quality  │ Background   │ bearers          │ Fine granularity       │
│ for all  │              │                   │                       │
└──────────┴──────────────┴───────────────────┴───────────────────────┘
```

### 2G (GSM): بدون QoS واقعی
- همه خدمات **مدار-گزارشی** هستند
- هر تماس یک شکاف زمانی اختصاصی می‌گیرد ← کیفیت یکسان برای همه
- نیازی به تمایز نیست (فقط صدا + SMS)

### 3G (UMTS): چهار کلاس ترافیک
| کلاس | تأخیر | مثال |
|-------|-------|---------|
| مکالمه‌ای | سختگیرانه (کمتر از 150ms) | صدا، تماس ویدیویی |
| پخش جریانی | متوسط (کمتر از 1s) | پخش جریانی ویدیو |
| تعاملی | متغیر | مرور وب |
| پس‌زمینه | بهترین تلاش | ایمیل، دانلودها |

### LTE (4G): QoS مبتنی بر حامل
- **حامل‌های EPS** با پارامترهای QoS مشخص معرفی شدند
- **QCI** (شناسه کلاس QoS): کلاس‌های استانداردشده
- **ARP** (اولویت تخصیص و نگهداری)
- حامل‌های **GBR** (نرخ بیت تضمین‌شده) در برابر **Non-GBR**

### 5G NR: QoS مبتنی بر جریان
- **جریان‌های QoS** شناسایی‌شده با **QFI** (شناسه جریان QoS)
- **5QI** جایگزین QCI با مقادیر بیشتر می‌شود
- **QoS بازتابی** برای رفتار UL ساده‌شده
- دانه‌بندی دقیق‌تر: چندین جریان در هر نشست PDU

## 3. QoS مبتنی بر حامل در LTE

### مفهوم حامل

```
┌────────────────────────────────────────────────────────────┐
│                    EPS BEARER ARCHITECTURE                   │
│                                                            │
│  ┌─────┐          ┌─────┐          ┌─────┐    ┌───────┐  │
│  │ UE  │──────────│eNB  │──────────│S-GW │────│P-GW   │  │
│  └─────┘  Radio   └─────┘   S1-U   └─────┘S5/8└───────┘  │
│           Bearer            Bearer          Bearer         │
│                                                            │
│  ◄──────── Radio Bearer ────────►                          │
│  ◄──────────── S1 Bearer ──────────────►                   │
│  ◄──────────────── S5/S8 Bearer ────────────────────►      │
│  ◄═══════════════ EPS Bearer (end-to-end) ══════════════►  │
│                                                            │
│  Each EPS Bearer = ONE QCI + ONE ARP                       │
└────────────────────────────────────────────────────────────┘
```

**حامل = تونل GTP-U با پارامترهای QoS مشخص (QCI + ARP + نرخ بیت)**

### حامل‌های پیش‌فرض در برابر اختصاصی

| جنبه | حامل پیش‌فرض | حامل اختصاصی |
|--------|---------------|-----------------|
| ایجاد | در اتصال PDU (اتصال) | در صورت تقاضا (با محرک) |
| طول عمر | همیشه فعال (تا جداسازی) | موقت (قابل آزادسازی) |
| QoS | بهترین تلاش (QCI 9) | QoS مشخص (هر QCI) |
| نوع | همیشه Non-GBR | GBR یا Non-GBR |
| آدرس IP | همراه حامل تخصیص می‌یابد | IP پیش‌فرض را به اشتراک می‌گذارد |
| هدف | دسترسی اینترنت | VoLTE، ویدیو، بازی |

### ARP (اولویت تخصیص و نگهداری)

ARP تعیین می‌کند آیا یک حامل می‌تواند در حین ازدحام برقرار شود:

| پارامتر | مقادیر | هدف |
|-----------|--------|---------|
| سطح اولویت | 1-15 (1=بالاترین) | اهمیت نسبی |
| قابلیت پیش‌گیری | بله/خیر | آیا این حامل می‌تواند دیگران را پیش‌گیری کند؟ |
| آسیب‌پذیری پیش‌گیری | بله/خیر | آیا این حامل می‌تواند پیش‌گیری شود؟ |

**سناریوی نمونه:**
```
Congestion situation - resources are full:

Bearer A: Priority=5, Pre-emption Capability=Yes
Bearer B: Priority=10, Pre-emption Vulnerability=Yes

→ Bearer A can preempt (remove) Bearer B to get resources
→ Emergency calls (Priority=1) can preempt regular calls
```

### حامل‌های GBR در برابر Non-GBR

```
┌─────────────────────────────────────────────────────┐
│              GBR BEARER                              │
│  ┌───────────────────────────────────┐              │
│  │  Guaranteed Bit Rate (GBR)        │              │
│  │  ═══════════════════ ← guaranteed │              │
│  │  Maximum Bit Rate (MBR)           │              │
│  │  ─────────────────── ← cap        │              │
│  │                                   │              │
│  │  Resources RESERVED at admission  │              │
│  │  Used for: Voice, Video calls     │              │
│  └───────────────────────────────────┘              │
├─────────────────────────────────────────────────────┤
│              NON-GBR BEARER                         │
│  ┌───────────────────────────────────┐              │
│  │  No guaranteed rate               │              │
│  │  ~~~~~~~~~~~~~~~~~~~~~~~~ ← best  │              │
│  │                            effort │              │
│  │  Limited by APN-AMBR / UE-AMBR    │              │
│  │                                   │              │
│  │  No resource reservation          │              │
│  │  Used for: Web, Email, Apps       │              │
│  └───────────────────────────────────┘              │
└─────────────────────────────────────────────────────┘
```

### محدودیت‌های QoS در LTE

1. **دانه‌بندی درشت**: یک QCI در هر حامل ← یک حامل در هر نوع خدمت
2. **سربار حامل**: هر QCI جدید نیازمند یک تونل GTP جدید است
3. **پر سیگنالینگ**: راه‌اندازی حامل اختصاصی نیازمند سیگنالینگ کامل NAS/S1AP است
4. **غیرانعطاف‌پذیر**: نمی‌توان ترافیک با QoS متفاوت را در یک حامل ترکیب کرد
5. **QCIهای محدود**: فقط 9 مقدار استاندارد (با MCX به حدود 20 گسترش یافته)

## 4. QoS مبتنی بر جریان در 5G

### مفهوم کلیدی: جریان QoS

```
┌─────────────────────────────────────────────────────────────────┐
│                   5G QoS ARCHITECTURE                            │
│                                                                 │
│  ┌──────── PDU Session ────────────────────────────────┐        │
│  │                                                     │        │
│  │  ┌─── QoS Flow 1 (QFI=1, 5QI=1) ──── Voice ─┐    │        │
│  │  │  SDF: src=UE, dst=IMS, proto=RTP           │    │        │
│  │  └────────────────────────────────────────────┘    │        │
│  │                                                     │        │
│  │  ┌─── QoS Flow 2 (QFI=2, 5QI=2) ──── Video ─┐    │        │
│  │  │  SDF: src=UE, dst=IMS, proto=RTP/video     │    │        │
│  │  └────────────────────────────────────────────┘    │        │
│  │                                                     │        │
│  │  ┌─── QoS Flow 3 (QFI=3, 5QI=9) ──── Web ───┐    │        │
│  │  │  SDF: src=UE, dst=*, proto=TCP             │    │        │
│  │  └────────────────────────────────────────────┘    │        │
│  │                                                     │        │
│  │  All flows share ONE N3/N9 GTP-U tunnel            │        │
│  │  (QFI marked in GTP-U extension header)            │        │
│  └─────────────────────────────────────────────────────┘        │
│                                                                 │
│  UE ──── gNB ──── UPF ──── DN                                  │
│      N3(GTP-U)  N9(GTP-U)                                      │
│      QFI in hdr  QFI in hdr                                    │
└─────────────────────────────────────────────────────────────────┘
```

**تفاوت‌های کلیدی با LTE:**
- چندین جریان QoS یک نشست PDU واحد (یک تونل GTP) را به اشتراک می‌گذارند
- QFI (6 بیتی) جریان را درون تونل شناسایی می‌کند
- نیازی به ایجاد/حذف حامل‌ها نیست ← سیگنالینگ کمتر
- دانه‌بندی دقیق‌تر با سربار کمتر

### قواعد QoS

قواعد QoS به UE می‌گویند چگونه ترافیک پیوند بالاسو را طبقه‌بندی کند:

```
QoS Rule Structure:
┌────────────────────────────────────┐
│  Rule ID                           │
│  Rule Precedence (priority)        │
│  QFI (target QoS flow)            │
│  Packet Filter(s):                │
│    - Source IP/Port               │
│    - Destination IP/Port          │
│    - Protocol                     │
│    - Type of Service              │
│    - Flow Label                   │
└────────────────────────────────────┘

Example:
  Rule 1: dst=10.0.0.5, proto=RTP, port=5060 → QFI=1 (voice)
  Rule 2: dst=10.0.0.5, proto=RTP, port=8000 → QFI=2 (video)
  Rule 3: default (match all)                 → QFI=3 (best effort)
```

### QoS بازتابی

```
┌──────────────────────────────────────────────────────────┐
│              REFLECTIVE QoS MECHANISM                      │
│                                                          │
│  1. Network sends DL packet with:                        │
│     - QFI = X                                            │
│     - RQI = 1 (Reflective QoS Indication)               │
│                                                          │
│  2. UE observes DL packet headers:                       │
│     - Source IP/Port → becomes UL Destination            │
│     - Destination IP/Port → becomes UL Source            │
│     - QFI = X → UE uses same QFI for reply              │
│                                                          │
│  3. UE creates "derived QoS rule" automatically:         │
│     - No explicit QoS rule signaling needed!             │
│     - Timer-based: rule valid for RQ Timer duration      │
│                                                          │
│  Benefit: Reduces signaling for establishing QoS rules   │
│  Use case: When UE doesn't know server IP in advance     │
└──────────────────────────────────────────────────────────┘
```

## 5. نگاشت و اجرای QoS

### نمودار نگاشت QoS سرتاسری

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    5G QoS MAPPING (End-to-End)                           │
│                                                                         │
│  APPLICATION LAYER                                                      │
│  ┌──────────────────────────────────────────────────┐                   │
│  │  IP Packets (SDF = Service Data Flow)            │                   │
│  │  Voice pkt | Video pkt | Web pkt | IoT pkt      │                   │
│  └──────┬───────────┬──────────┬──────────┬─────────┘                   │
│         │           │          │          │                             │
│  QoS CLASSIFICATION (SDF → QoS Flow)                                   │
│  ┌──────▼───────────▼──────────▼──────────▼─────────┐                   │
│  │  QoS Rules / SDF Templates                       │                   │
│  │  Match: 5-tuple (src/dst IP, src/dst port, proto)│                   │
│  │  Action: Assign QFI                              │                   │
│  └──────┬───────────┬──────────┬──────────┬─────────┘                   │
│         │QFI=1      │QFI=2     │QFI=3     │QFI=4                        │
│         ▼           ▼          ▼          ▼                             │
│  QoS FLOW LAYER                                                         │
│  ┌─────────────┬────────────┬───────────┬───────────┐                   │
│  │ Flow(5QI=1) │Flow(5QI=2) │Flow(5QI=9)│Flow(5QI=82)│                  │
│  │ Voice       │ Video      │ Web       │ URLLC     │                   │
│  └──────┬──────┴─────┬──────┴─────┬─────┴─────┬─────┘                   │
│         │            │            │            │                         │
│  DRB MAPPING (gNB decides)                                              │
│  ┌──────▼────────────▼────────────▼────────────▼─────┐                   │
│  │  DRB 1 (GBR)  │  DRB 2 (GBR)  │  DRB 3 (Non-GBR)│                   │
│  │  QFI=1         │  QFI=2         │  QFI=3, QFI=4   │                   │
│  └────────────────┴────────────────┴─────────────────┘                   │
│                                                                         │
│  NOTE: Multiple Non-GBR flows CAN share one DRB                         │
│        GBR flows typically get dedicated DRBs                            │
└─────────────────────────────────────────────────────────────────────────┘
```

### نقش هر عنصر شبکه

| عنصر | نقش QoS | اقدامات |
|---------|----------|---------|
| **PCF** | تصمیم سیاست | قواعد PCC را ایجاد می‌کند، 5QI/ARP را تعیین می‌کند، به SMF می‌فرستد |
| **SMF** | کنترل QoS | پروفایل‌های QoS را مشتق می‌کند، قواعد QoS را نصب می‌کند، UPF را پیکربندی می‌کند |
| **UPF** | اجرای DL | تشخیص SDF، علامت‌گذاری QFI، دروازه‌بندی، پلیسینگ، محدودسازی نرخ |
| **gNB** | زمان‌بندی رادیویی | جریان‌های QoS را به DRBها نگاشت می‌کند، بر اساس 5QI زمان‌بندی می‌کند، AMBR را اجرا می‌کند |
| **UE** | طبقه‌بندی UL | قواعد QoS را اعمال می‌کند، بسته‌های UL را به جریان‌های QoS نگاشت می‌کند |

### معماری اجرای QoS

```
┌──────────────────────────────────────────────────────────────────┐
│              QoS POLICY & ENFORCEMENT ARCHITECTURE                │
│                                                                  │
│  ┌─────┐  PCC Rules   ┌─────┐  QoS Profile  ┌─────┐           │

│     │                     │                                      │

│     │                     ▼                                      │
│     │               ┌─────────┐                                 │
│     │               │   UPF   │  Enforces:                      │
│     │               │         │  - SDF detection                │

│     │                                                            │
│     │  ┌─────┐  Service Request  ┌─────┐                       │
│     └──│ AF  │◄─────────────────│ App │                        │
│        │(IMS)│                   │     │                        │

│                                                                  │
```

## 7. GBR در برابر Non-GBR در برابر GBR حساس-به-تأخیر

### سه نوع منبع در 5G

```
┌─────────────────────────────────────────────────────────────────────┐
│                    5G QoS RESOURCE TYPES                             │
│                                                                     │
│  ┌─────────────────────┐  ┌─────────────────────┐                  │
│  │       GBR            │  │     Non-GBR          │                  │
│  │                     │  │                     │                  │
│  │  ▓▓▓▓▓▓▓▓▓▓ GFBR   │  │  No rate guarantee  │                  │
│  │  ░░░░░░░░░░ (up to  │  │  ~~~~~~~~~~~~~~~~   │                  │
│  │             MFBR)   │  │  Limited by AMBR    │                  │
│  │                     │  │                     │                  │
│  │  Resources reserved │  │  Best effort        │                  │
│  │  Admission control  │  │  No admission ctrl  │                  │
│  │                     │  │                     │                  │
│  │  Voice, Video call  │  │  Web, Email, Apps   │                  │
│  └─────────────────────┘  └─────────────────────┘                  │
│                                                                     │
│  ┌─────────────────────────────────────────────┐                    │
│  │       Delay-Critical GBR (DC-GBR)           │                    │
│  │                                             │                    │
│  │  ▓▓▓▓▓▓▓▓▓▓ GFBR + Bounded Delay           │                    │
│  │                                             │                    │
│  │  Additional parameter:                      │                    │
│  │    Maximum Data Burst Volume (MDBV)         │                    │
│  │    → Guarantees delay bound for burst       │                    │
│  │                                             │                    │
│  │  URLLC: Industrial automation, V2X,         │                    │
│  │         Remote surgery, AR/VR               │                    │
│  └─────────────────────────────────────────────┘                    │
└─────────────────────────────────────────────────────────────────────┘
```

### پارامترها بر اساس نوع منبع

| پارامتر | GBR | Non-GBR | DC-GBR |
|-----------|:---:|:-------:|:------:|
| 5QI | ✓ | ✓ | ✓ |
| ARP | ✓ | ✓ | ✓ |
| GFBR (نرخ بیت جریان تضمین‌شده) | ✓ | ✗ | ✓ |
| MFBR (حداکثر نرخ بیت جریان) | ✓ | ✗ | ✓ |
| Session-AMBR | ✗ | ✓ | ✗ |
| حداکثر حجم انفجار داده | ✗ | ✗ | ✓ |
| بودجه تأخیر بسته | ✓ | ✓ | ✓ (سختگیرانه) |
| کنترل پذیرش | لازم | لازم نیست | لازم |
| رزرو منابع | بله | خیر | بله |

### توضیح پارامترهای نرخ

```
GFBR = Guaranteed Flow Bit Rate
  → Network MUST provide at least this rate
  → If congestion, GBR flows protected up to GFBR

MFBR = Maximum Flow Bit Rate  
  → Network MAY provide up to this rate
  → Excess above MFBR is dropped/shaped

Example (VoLTE):
  GFBR = 40 kbps (AMR-NB codec rate)
  MFBR = 80 kbps (with overhead margin)

Example (Video Call):
  GFBR = 1 Mbps (minimum acceptable quality)
  MFBR = 4 Mbps (HD quality when resources available)
```

## 8. AMBR (حداکثر نرخ بیت تجمیعی)

### سلسله‌مراتب AMBR

```
┌─────────────────────────────────────────────────────────────────┐
│                      AMBR HIERARCHY                              │
│                                                                 │
│  ┌───────────────────────────────────────────────────────┐      │
│  │                 UE-AMBR (per UE)                      │      │
│  │  Aggregate cap across ALL Non-GBR QoS flows          │      │
│  │  of all PDU sessions                                  │      │
│  │  Example: UE-AMBR = 100 Mbps DL / 50 Mbps UL        │      │
│  │  (stored in subscription data)                        │      │
│  │                                                       │      │
│  │  ┌─────────────────────┐  ┌─────────────────────┐    │      │
│  │  │ Session-AMBR (Sess1)│  │ Session-AMBR (Sess2)│    │      │
│  │  │ 50 Mbps DL/25 UL   │  │ 30 Mbps DL/15 UL   │    │      │
│  │  │                     │  │                     │    │      │
│  │  │  ┌───┐ ┌───┐ ┌───┐│  │  ┌───┐ ┌───┐       │    │      │
│  │  │  │F1 │ │F2 │ │F3 ││  │  │F4 │ │F5 │       │    │      │
│  │  │  │Non│ │Non│ │GBR││  │  │Non│ │GBR│       │    │      │
│  │  │  │GBR│ │GBR│ │   ││  │  │GBR│ │   │       │    │      │
│  │  │  └───┘ └───┘ └───┘│  │  └───┘ └───┘       │    │      │
│  │  │                     │  │                     │    │      │
│  │  │  Session-AMBR caps  │  │  Session-AMBR caps  │    │      │
│  │  │  F1+F2 (not F3)    │  │  F4 (not F5)        │    │      │
│  │  └─────────────────────┘  └─────────────────────┘    │      │
│  │                                                       │      │
│  │  UE-AMBR caps: F1+F2+F4 (all Non-GBR across sess)   │      │
│  │  GBR flows (F3, F5) are NOT limited by AMBR          │      │
│  └───────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘
```

### نقاط اجرای AMBR

| نوع AMBR | دامنه | اجرا در | اعمال بر |
|-----------|-------|-------------|-----------|
| UE-AMBR | تمام نشست‌ها | gNB (RAN) | تمام جریان‌های Non-GBR، تمام نشست‌ها |
| Session-AMBR | در هر نشست PDU | UPF | جریان‌های Non-GBR در آن نشست |

**قواعد کلیدی:**
- AMBR **فقط** بر جریان‌های Non-GBR اعمال می‌شود
- جریان‌های GBR با MFBR خود محدود می‌شوند، نه AMBR
- UE-AMBR ≥ مجموع Session-AMBRها (به‌طور منطقی)
- به‌طور جداگانه برای UL و DL اجرا می‌شود

## خلاصه: نکات کلیدی

| مفهوم | نکته کلیدی |
|---------|-----------|
| هدف QoS | خدمات مختلف نیازمند رفتار شبکه‌ای متفاوتی هستند |
| QCI (LTE) | 9 کلاس استاندارد، یکی در هر حامل |
| 5QI (5G) | بیش از 90 کلاس، در هر جریان QoS |
| حامل (LTE) | نگاشت 1:1 با QCI، تونل GTP جدا |
| جریان QoS (5G) | چندین جریان یک نشست PDU را به اشتراک می‌گذارند، سیگنالینگ سبک‌تر |
| GBR | نرخ تضمین‌شده، کنترل پذیرش، منبع رزروشده |
| Non-GBR | بهترین تلاش، محدودشده با AMBR |
| DC-GBR | GBR + تأخیر کران‌دار (MDBV)، برای URLLC |
| AMBR | سقف تجمیعی بر Non-GBR (سطح UE و سطح نشست) |
| QoS بازتابی | UE مقدار QoS پیوند بالاسو را از پیوند پایین‌سو مشتق می‌کند (کاهش سیگنالینگ) |
| PCF | مغز سیاست، قواعد PCC را ایجاد می‌کند |
| UPF | طبقه‌بند و مجری DL |
| gNB | زمان‌بند رادیویی، نگاشت DRB، UE-AMBR |
